# Improvement research tools

Own dated research ingestion, reports, and progress records, not product implementation or proof that proposals shipped. Scripts can contain fixed dates and destinations; inspect them before reuse.

- Confirm inputs, outputs, and overwrite targets. Preserve other investigations.
- Validate owner, real path/line range, unique identifier, and required fields. Correct counts do not compensate for nonexistent evidence.
- Check offline/no-URL output requirements in both source JSON and rendered output. Display conversion must preserve evidence.
- Knowledge checks read the specified files, configuration, and links; they do not edit vault notes or child source for convenience.
- Attach observed evidence and reasons to complete/blocked states. Generation success is not implementation completion.

Syntax-check changed Python files. Run a validator only when its specified inputs exist; report missing prerequisites instead of fabricating them. `check_counts.py` checks existing research counts, paths, and display restrictions. Use `init_progress_ledger.py --check` for inspection without creation or state mutation. Report the modified tool, input scope, and output path.
