[KPLG-004] promotion apply 후 자동 검증 게이트가 없음

[KVCL-001] ranking action이 raw interaction rows를 두 번 읽고 JS에서 집계함

ranking section은 overall과 weekly ranking을 동시에 요청하고, 각 server action은 `tool_clicks` rows를 가져와 JavaScript로 count를 집계한다. 데이터가 늘수록 DB에서 집계해야 할 작업을 app server가 반복 수행하고 전송 row 수가 커진다.

권고: Supabase RPC, view, materialized summary table 중 하나로 count/grouping을 DB에서 수행한다. overall과 weekly를 한 RPC에서 함께 반환하거나 cached summary를 주기적으로 갱신한다.

[KVCL-002] CSV import가 파일 크기와 행 수를 제한하지 않음

multipart 전체를 `formData()`로 읽고 파일 전체를 `text()`로 메모리에 올린 뒤 모든 유효 행을 한 번에 insert한다. 큰 파일이나 과다 행 입력이 API timeout, 메모리 사용량 급증, DB 대량 쓰기로 이어질 수 있다.

위치: keelim-vercel/app/api/products/import/route.ts:172

권고: 파일 크기, row 수, batch size 상한을 두고 초과 시 413 또는 400을 반환하며 batch insert로 나눈다.

[KVCL-003] OG parser가 외부 요청 대상의 scheme·host를 제한하지 않음

입력 URL은 `new URL` 통과만 확인하고 그대로 서버 측 `fetch`에 전달된다. 내부망, metadata endpoint, 비정상 scheme 같은 서버 측 요청 대상이 차단되지 않아 SSRF 성격의 정확성·보안 문제가 된다.

위치: keelim-vercel/app/api/og-parser/route.ts:15

권고: 문자열 타입, 허용 protocol, public hostname, DNS/IP private range 차단을 검증하고 실패 시 400을 반환한다.

[KVCL-004] fear-greed API가 클라이언트가 기대하는 data 필드를 반환하지 않음

route는 `score`, `label`, `timestamp`를 최상위로 반환하지만 market query hook은 `result.data`를 FearGreedData로 읽는다. API가 성공해도 소비자는 undefined를 받을 수 있다.

[RICH-001] Admin API 라우터에 인증 dependency가 없음

`/api/admin` 라우터가 전역 인증·인가 dependency 없이 선언되어 GET/POST 관리 API가 앱 노출 범위에 그대로 따라간다. CORS allowlist는 브라우저 정책일 뿐 서버 측 인증이 아니므로 백엔드 포트가 노출되면 관리 데이터를 읽거나 작업을 실행할 수 있다.

위치: rich/app/api/admin.py:24

권고: 라우터 전역 `Depends(require_admin)`를 추가하고 Supabase/세션/JWT에서 admin 권한을 검증한다. 모든 admin route에 401/403 테스트를 추가한다.

[RICH-002] KIS quote 호출이 요청자 권한과 분리됨

fear-candidates 흐름은 서버의 기존 KIS 인증 상태만 확인하고 API 요청자의 admin 권한은 확인하지 않는다. 서버가 이미 KIS 세션을 가진 상태라면 무인증 호출자가 현재가 검증을 트리거할 수 있다.

위치: rich/app/services/krx_kis_fear_candidates.py:946

권고: 라우트 진입 전에 admin auth를 강제하고 KIS session owner와 요청자를 연결한다. KIS 호출은 감사 로그와 rate limit을 적용한다.

[RICH-003] Open Trading 라우트를 인증 래퍼 없이 같은 앱에 등록

Rich FastAPI 앱이 vendor Open Trading 라우트를 같은 process와 CORS 설정 아래 포함한다. 벤더 내부는 별도 분석 대상이 아니지만, 통합 지점에 auth boundary가 없어 KIS·전략 실행 계열 endpoint가 admin 보호와 분리되지 않는다.

위치: rich/app/main.py:48

권고: Open Trading 통합을 인증된 sub-app 또는 proxy adapter로 감싸고 허용 route/method를 명시한다. 민감 action은 별도 admin permission을 요구한다.

[RICH-004] Service-role 키가 일반 API Settings에 상주

`Settings`가 FastAPI runtime에서 Supabase service-role key를 직접 로드한다. admin route 인증이 약한 상태에서 하나의 route bug가 DB 전체 권한을 가진 credential 접근면으로 확대될 수 있다.

위치: rich/app/core/settings.py:26

권고: public API용 설정과 privileged job 설정을 분리한다. API 프로세스에는 service-role을 주입하지 않고 필요한 작업은 권한 제한 RPC나 내부 worker로 위임한다.

[YTB-001] CI 진입점이 패키지 메타데이터에 정의되어 있지 않음

`pyproject.toml`은 CLI 엔트리포인트 `ern`만 노출하고 lint, test, lock check, render smoke 같은 검증 명령을 선언하지 않는다. GitHub Actions를 추가해도 각 작업자가 암묵 지식으로 명령을 조합해야 해 자동화 재현성이 낮다.

위치: youtube/pyproject.toml:14

[YTB-002] Playwright 의존성이 pyproject에 선언되어 있지 않음

위치: youtube/scripts/collect_threads_profile.py:15

권고: 브라우저 크롤러를 optional dev 그룹으로 분리하고 CI import smoke에서 해당 그룹 설치 여부를 명시한다.

[YTB-003] 명시 후보 경로가 repo 내부로 제한되지 않음

권고: 후보 경로가 `.skillopt` 또는 허용된 후보 루트 아래인지 검사하고, 벗어나면 실패시키는 guard를 추가한다.

[YTB-004] 전체 본문 저장 옵션이 CI artifact 누출 위험을 만듦

`--include-full-text`가 켜지면 수집된 본문 전체를 raw JSON에 저장한다. CI artifact 업로드나 실패 로그 수집과 결합되면 저작권/개인정보성 텍스트가 필요 이상으로 보존될 수 있다.

위치: youtube/scripts/collect_threads_profile.py:555

권고: CI에서는 full text 옵션을 금지하고, 명시적 `--allow-full-text-artifact` 같은 로컬 전용 플래그와 경고를 추가한다.

[AWUI-001] Progress가 Radix Root에 value를 전달하지 않음

Progress 컴포넌트는 value를 구조분해한 뒤 Indicator transform에만 쓰고 ProgressPrimitive.Root에는 넘기지 않는다. 화면에는 진행률이 보여도 aria-valuenow가 빠지거나 Radix의 진행률 접근성 상태가 깨질 수 있다.

위치: all-web-ui/src/components/progress.tsx:11

권고: ProgressPrimitive.Root에 value={value}와 max를 전달하고, indeterminate일 때는 명시적으로 value를 undefined로 처리한다.

[AWUI-002] async sink 실패를 await/catch하지 않음

`TelemetrySink.emit`은 Promise를 반환할 수 있지만 `createTelemetryEmitter.emit`은 await하지 않고 즉시 `{ emitted: true }`를 반환한다. sink reject가 unhandled rejection이 되거나 실제 전송 실패를 성공으로 보고하는 계약 오류가 생긴다.

위치: all-web-ui/src/telemetry.ts:168

권고: `emit`을 async로 만들거나 fire-and-forget 전용 `emitAsync`/`emit` 계약을 분리하고 실패 result를 반환한다.

high

[AWUI-003] telemetry payload의 알 수 없는 필드를 통과시킴

`validatePayload`는 required/optional 필드 타입만 검사하고 payload의 추가 key를 거부하거나 제거하지 않는다. 소비자가 실수로 PII나 내부 상태를 넣어도 `defineTelemetryEvent`가 그대로 sink로 전달해 privacy와 schema 안정성 문제가 된다.

위치: all-web-ui/src/telemetry.ts:174

권고: schema별 allowed key set을 만들고 unknown key는 validation error로 처리하거나 safe payload로 strip한다.

high

[AWUI-004] AlertTitle ref 타입이 heading 렌더링과 불일치

`AlertTitle`도 `<h5>`를 렌더링하면서 ref 타입은 `HTMLParagraphElement`로 선언한다. 디자인 시스템 primitive가 잘못된 DOM 타입을 내보내면 소비자 코드의 ref narrowing과 테스트 query 보조 타입이 틀어진다.

위치: all-web-ui/src/components/alert.tsx:29

권고: `React.forwardRef<HTMLHeadingElement, React.ComponentPropsWithoutRef<'h5'>>` 또는 제목 level을 prop으로 받는 heading primitive로 정리한다.
