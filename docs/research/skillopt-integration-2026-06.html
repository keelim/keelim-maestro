Executive Summary

SkillOpt는 Microsoft의 text-space optimizer로, LLM 가중치를 건드리지 않고(frozen agent) 에이전트의 자연어 스킬 문서(SKILL.md)를 학습 가능한 상태로 취급해 신경망 훈련의 규율 (epoch·batch·learning rate·validation gating)로 최적화한다. 산출물은 300~2,000 토큰의 best_skill.md 한 장이고 배포 시 추가 모델 호출이 0회다(컨텍스트로 읽힘). 결정적으로 SkillOpt는 평가를 direct chat / Codex CLI / Claude Code CLI 세 하니스에서 수행했고, 소스는 실제로 codex exec와 claude -p를 subprocess로 구동하며 최적화된 스킬을 .agents/skills/skillopt-target/SKILL.md에 써넣어 주입한다(원본 확인). 접목 방향은 둘: (A) 산출 스킬을 소비하거나 (B) 당신의 기존 SKILL.md를 SkillOpt로 학습. 단, v0.1.0 초기 단계이며 성능 수치는 저자 보고치, 훈련 API 비용은 선불로 크다.

1. SkillOpt란 무엇인가 High

한 줄 정의frozen LLM 에이전트용 재사용 가능한 자연어 스킬을, trajectory 기반 편집 + validation-gated 업데이트로 학습시켜 best_skill.md로 배포하는 text-space optimizer
만든 곳 / 라이선스Microsoft / MIT
릴리스v0.1.0 (PyPI, 2026-06-02), 약 5.1k stars
논문arXiv:2605.23904, Yifan Yang 외 15인, 27p — human·TextGrad·Trace2Skill·GEPA·EvoSkill 대비
스택Python 3.10+ (≈82%), HTML WebUI(≈17%)
설치pip install skillopt (+extras [alfworld] [webui] [claude])

해결하는 문제. 에이전트 "스킬"은 보통 수작업이거나 LLM 일회성 생성이라 재현·측정 가능한 개선 루프가 없다. SkillOpt는 "스킬 문서를 frozen agent의 학습 가능한 외부 상태로 두고, weight-space 최적화를 재현 가능하게 만든 규율로 훈련"한다.

왜 배포 친화적인가: 최적화 비용은 훈련 때 1회 선불, 추론 오버헤드 0 ("system prompt나 context에 떨어뜨리면 끝"). 가중치를 안 바꾸므로 파인튜닝이 아니고, 지식 주입이 아니라 행동·전략 개선이라 RAG와도 다르며, 검증 게이트로 단조(monotonic) 개선을 지향.

2. 핵심 방법론 — 신경망처럼 스킬을 "학습"한다 High

훈련 루프 (5단계)

Rollout → Reflect → Aggregate → Select → Update & Evaluate
(롤아웃)  (반성·채점) (집계)     (검증게이트) (스킬갱신·평가)
  1. Rollout & Score — 현재 스킬로 배치 과제 실행, 점수 수집
  2. Reflect — 별도 optimizer model이 실패 분석 → bounded edit(add/delete/replace) 후보 생성
  3. Aggregate — 편집 후보 집계
  4. Select (Validation Gating) — held-out 검증셋에서 점수가 엄격히 개선될 때만 채택 (hard=정확일치 / soft=부분점수)
  5. Update & Evaluate — 스킬 갱신 후 평가, epoch 경계서 slow/meta 업데이트로 안정화

DL 비유 매핑 (문서 dl-analogy.md, 원본 확인)

"natural-language 프롬프트 최적화는 신경망 훈련과 동일한 구조를 따른다."

4. 아키텍처 — 접목의 뼈대는 "3계층 분리" High

README: "target model, backend, harness는 고정한 채, 증거 수집·도구 사용·검증·출력 형식을 안내하는 절차가 진화한다." 접목 이해의 핵심은 세 역할 분리다.

역할무엇설정 위치당신 환경에서
Optimizer model편집(gradient) 제안model.optimizer / --optimizer_model강한 모델 (gpt-5.5, claude…)
Target modelfrozen, 과제 수행model.target / --target_model배포에 쓸 바로 그 모델
Harness (=target backend)target 실행 환경env TARGET_BACKEND (+ OPTIMIZER_BACKEND)direct chat(chat enum) 또는 codex_exec/claude_code_exec
두 소스 파일이 다른 계층을 담당(혼동 주의):
• claude_backend.py = Claude를 모델 백엔드로. API 직접호출 X, claude CLI를 -p로 호출. 인증은 claude 바이너리에 위임(CLAUDE_CLI_BIN), 기본 배포명 claude-sonnet-4-6.
• codex_harness.py = 이름과 달리 에이전트 하니스 계층. run_codex_exec+run_claude_code_exec+디스패처 run_target_exec 포함. target을 풀 에이전트 루프로 실행 → "+24.8 / +19.1"의 출처.

Backend enum(소스 backend_config.py 확인): optimizer = openai_chat | claude_chat | qwen_chat | minimax_chat; target = 여기에 codex_exec | claude_code_exec 추가(에이전트 하니스). 선택은 env OPTIMIZER_BACKEND/TARGET_BACKEND(기본 openai_chat), TARGET_BACKEND ∈ {codex_exec, claude_code_exec}면 agentic. Azure는 별도 enum이 아닌 OpenAI 호환 provider(openai_chat+env). Provider env: AZURE_OPENAI_*, OPENAI_API_KEY, ANTHROPIC_API_KEY, QWEN_API_BASE. (※ WebFetch 1차 요약의 "azure_openai/qwen" 표기는 실제 enum과 달라 cloned 소스로 정정.)

5. Codex · Claude Code 접목 메커니즘 High · clone+grep 검증

git clone --depth 1 후 실제 바이트로 대조 — 아래 인용은 행번호까지 일치.

스킬 주입 (양쪽 공통)

os.makedirs(os.path.join(work_dir, ".agents", "skills", "skillopt-target"), exist_ok=True)
skill_path = os.path.join(work_dir, ".agents", "skills", "skillopt-target", "SKILL.md")
# ... f.write(skill_md)

프롬프트 지시문(원본): "Read .agents/skills/skillopt-target/SKILL.md before answering ... do not call a Skill tool."

중요한 정정: 경로는 Claude Code 네이티브 위치 .claude/skills/가 아니라 크로스툴 규약 .agents/skills/다 (cloned 소스 grep .claude → 0건). 게다가 일부러 "Skill tool 호출하지 말고 직접 읽으라"고 강제 — 채점 결정성을 위해 네이티브 스킬 자동탐색을 우회한다. 즉 SKILL.md 파일 규약은 차용하되, Claude Code 스킬 디스커버리는 쓰지 않는다.

Claude Code 구동 — run_claude_code_exec

cmd = [
    str(config["path"]), "-p",
    "--output-format", "text",
    "--permission-mode", permission_mode or "bypassPermissions",
    "--add-dir", work_dir,
    "--tools", tools, "--allowedTools", tools,
]
cmd.extend(["--append-system-prompt", f"Profile: {config['profile']}"])

Codex 구동 — run_codex_exec

cmd = [
    str(config["path"]), "exec",
    "--skip-git-repo-check", "--color", "never",
    "-C", work_dir,
]
# 추가 플래그: --full-auto, --sandbox, -m <model>, --output-last-message ...

디스패처 run_target_exec()가 target backend(codex_exec/claude_code_exec)로 분기. trace 산출: codex_raw.txt, claude_raw.txt 등. 주요 함수: render_skill_md, prepare_workspace, parse_codex_raw, run_claude_code_exec, run_codex_exec, run_target_exec.

6. 당신의 환경에 접목하는 3가지 실전 경로

핵심 접점: 당신은 이미 Codex(codex:rescue/codex CLI runtime)와 Claude Code를 에이전트 하니스로 쓰고, 다수의 SKILL.md를 전역(~/.claude/skills/)에 유지한다. 당신의 기존 SKILL.md들이 곧 SkillOpt의 학습 대상 아티팩트다. (이 저장소엔 로컬 .claude/skills/·.agents/가 없음 — 전역 라이브러리 기준.)

경로 A — "소비자"로 접목 빠름 · 저비용

학습 완료된 스킬(ckpt/ 사전학습 또는 당신이 학습한 best_skill.md)을 그대로 배포.

  • Claude Code: ~/.claude/skills/<name>/SKILL.md로 배치 → 네이티브 디스커버리 노출. frontmatter(name/description) 추가 매핑 필요(SkillOpt는 .agents/+직접읽기라 그대로 복사하면 안 잡힐 수 있음).
  • Codex: AGENTS.md에 병합 또는 --append-system-prompt/프로필로 주입.
  • 오버헤드 0 · 위험 낮음 · 도메인 맞으면 즉효.

경로 B — "최적화 대상"으로 접목 핵심 가치

당신의 실제 과제로 스킬을 학습시키고 Codex/Claude Code 루프에서 검증.

  1. env 작성: skillopt/envs/<task>/에 dataloader.py(train/val/test split) + rollout.py + initial.md. _template/ 참고.
  2. 하니스 지정: target backend를 codex_exec/claude_code_exec로 → 배포할 그 루프에서 채점.
  3. 모델 분리: --optimizer_model(강) ≠ --target_model(배포). Claude 쓰려면 pip install skillopt[claude] + claude CLI 인증.
  4. 실행: 
    python scripts/train.py --config configs/<task>/default.yaml \
    --optimizer_model <strong> --target_model <deploy> \
    --num_epochs 4 --batch_size 40 --workers <N>
# 오버라이드 예: optimizer.learning_rate=16
  5. 산출: best_skill.md(+ skills/skill_vXXXX.md 스냅샷) → 경로 A로 배포.

훈련 API 비용 선불·상당 · 채점 함수 품질에 좌우 · 측정 가능한 단조 개선.

경로 C — 파이프라인 통합 워크플로우 결합

  • 데이터 소스: codex:rescue 등 실행 로그·trace를 train/val 과제로 수확.
  • 주기 학습: 새 과제 누적 시 재학습, 검증 통과한 best_skill.md만 스킬 라이브러리로 승격(이전 세션 goal/조건 자동화와 결합).
  • 멀티-하니스 전이: Codex 학습 → Claude Code 전이 테스트로 cross-harness transfer 검증.

Key Takeaways

  1. 새로 만들 것 없음 — 연결만 하면 된다. SkillOpt는 Codex·Claude Code를 이미 1급 하니스로 구동하며 스킬을 .agents/skills/skillopt-target/SKILL.md로 주입(원본 확인).
  2. 가장 큰 가치는 경로 B — 당신의 실제 과제로 기존 SKILL.md를 학습시켜 측정 가능한 개선을 얻는 것.
  3. 3계층(optimizer / target / harness)을 분리해 사고하라. Codex·Claude Code가 꽂히는 곳은 "harness=target backend".
  4. .agents/ ↔ .claude/ 매핑 + frontmatter가 배포 시 실질 함정. 채점/배포 동작 차이를 재검증.
  5. 작게 시작: 성공 기준 명확한 과제 1개 + 작은 epoch로 PoC → 비용/효과 측정 후 확대.
